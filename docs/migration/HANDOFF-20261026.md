# DPA intelligence handoff

2026-10-26 owner decision: DPAAgent becomes the intelligence development home.
The native DPA product retains hardware operations and deterministic processing.
This tranche receives 203 curated source/test/config files, with byte receipts in
source-manifest-20261026.json. It does not import the private product's Git history.

The existing pi/Electron runtime remains in place. Legacy C++ providers, sessions,
diagnostic rules, campaign planning/evidence and Qt UX are not silently installed
as a second agent runtime. Their application source and tests are received in `legacy/dpa-embedded/`; parallel
monitoring changes are isolated in `legacy/monitoring-wip/`. Full original Git history
and historical evidence remain private under preserved tags and the per-file portfolio.
Runtime adaptation and validation remain pending; this archive is not a second active agent.

The public manifest deliberately contains source identities rather than private
runtime logs, transcripts, device data, screenshots, databases or license payloads.
See NOTICE.md: migration does not create a new source license.

## Bridge contract actually available

Start an authorized DPA build manually with `DPA_ENABLE_AGENT_BRIDGE=1` after the
native transition is adopted. The current pre-transition main already loads the
compatibility service; the explicit switch applies to the transition build.
The read-only client reads `%LOCALAPPDATA%/DPA-2026/mcp/bridge.json`, requires
`127.0.0.1`, an integer port and `read_token`, and discovers actual read tools.
Example existing tool name: `dpa.project.current`. No writable token fallback exists.

The older desktop documentation refers to `tools/dpa-mcp/server.js`,
`ExternalAgentBridge`, `dpa_ensure_running` and confirmed write operations. This
describes another protocol and is not proof those tools work against this product.
No automatic launcher, tool-name translation or privilege upgrade is introduced.
Native confirmation/interlocks must remain authoritative if a writable protocol
is implemented later. Client transport rejects redirects and off-origin endpoints.
